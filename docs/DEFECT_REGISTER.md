# Реестр дефектов TaskBar

Разделяйте **учебные искусственно внесённые дефекты** от реально найденных при тестировании.

| ID | Источник | Симптом | Причина | Исправление | Приоритет | Статус | Доказательство |
|---|---|---|---|---|---|---|---|
| LAB-01 | Debugger (демонстрация) | `2 / 6` ошибочно показывается `0%` | целочисленное деление | `toDouble`, `roundToInt`, clamp в `ProgressCalculator` | P1 | Исправлено в production-коде; демонстрация в debug оставлена | скриншот 02 после запуска |
| LAB-02 | Layout Inspector (демонстрация) | два текста перекрываются | два дочерних элемента по центру одного Box | отдельная компоновка Row, переключатель в Debug Lab | P2 | Исправляемый демонстрационный кейс | скриншоты 04 до/после |
| LAB-03 | Break on exceptions (демонстрация) | NPE / IOB / main-thread networking | отсутствующая null-check / неверный индекс / блокирующая сеть | null-safety / `getOrNull` / Retrofit suspend в IO | P1 | Исправлено в реальных рабочих флоу; debug-only код оставлен для анализа | скриншоты 03 |
| LAB-04 | LeakCanary (демонстрация) | Activity удерживается после закрытия | сильная ссылка в singleton | `DebugLeakScenario.release()` | P1 | Исправление доступно в debug, фактическую детекцию подтвердить | скриншоты 13 |
| DEF-01 | Фактическое тестирование | ЗАПОЛНИТЬ | ЗАПОЛНИТЬ | ЗАПОЛНИТЬ | P0/P1/P2 | Open/In Progress/Fixed/Verified | ссылка |

**P0:** потеря данных, падение, сбой основного сценария. **P1:** заметное функциональное несоответствие. **P2:** визуальный или не блокирующий дефект.
