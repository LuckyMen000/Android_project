# TaskBar — Test Plan, 10 ручных тест-кейсов

**Объект:** TaskBar 1.1.0-rgr3. **Ответственный:** заполнить. **Дата:** заполнить.

Для каждого кейса заполнить поля: **Устройство/API**, **Actual**, **PASS/FAIL/BLOCKED/NOT RUN**, **Screenshot**, **Defect ID**. Таблица ниже — запланированные шаги и ожидаемые результаты, не протокол уже прошедших тестов.

| ID | Предусловие и шаги | Ожидаемый результат | Приоритет |
|---|---|---|---|
| TC-01 | Открыть «Задачи» → «+» → ввести «Курсовая» → сохранить | Новая задача появляется в списке; после перезапуска сохранена | P0 |
| TC-02 | Открыть создание → оставить название пустым → сохранить | Сохранение блокируется, показывается подсказка валидации | P0 |
| TC-03 | Создать задачу → изменить название/дату/приоритет → сохранить | Изменения сохраняются, id и статус задачи не теряются | P0 |
| TC-04 | Создать задачу → пометить выполненной → вернуть активной | Статус, прогресс и счётчики обновляются | P0 |
| TC-05 | Создать несколько задач → найти по части названия и описания → очистить поиск | Корректный регистронезависимый фильтр, видны все после сброса | P1 |
| TC-06 | Создать задачу → удалить → подтвердить/отменить удаление | При отмене данные сохранены, при подтверждении запись удалена | P0 |
| TC-07 | В настройках переключить тёмную/светлую тему → перезапустить приложение | Выбранная тема сохраняется; текст и кнопки читаемые | P1 |
| TC-08 | Создать черновик → повернуть portrait→landscape→portrait, свернуть/развернуть | Не возникает крэш; несохранённый ввод восстанавливается при recreate; базовый UI доступен | P1 |
| TC-09 | Создать задачу → выключить интернет → закрыть приложение и открыть → открыть главную | Задачи доступны офлайн, вместо цитаты из сети показывается fallback, без ANR | P0 |
| TC-10 | Создать задачи → принудительно остановить процесс (`adb shell am force-stop kz.taskbar.app`) → открыть TaskBar | Данные Room сохранены, интерфейс и счётчики восстановлены | P0 |

## Monkey

```bash
mkdir -p evidence/rgr3
adb shell monkey -p kz.taskbar.app --throttle 200 -v 1000 > evidence/rgr3/11_monkey.txt 2>&1
```

Перед запуском убедитесь, что активна **debug**-сборка и пользовательские данные не нужны (Monkey производит случайные нажатия). После прогона зафиксируйте `Events injected`, `ANR`, `CRASH`, количество событий, конкретные сбои и шаги повторения. При найденной ошибке создайте запись в `DEFECT_REGISTER.md`.
